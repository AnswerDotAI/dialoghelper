Reaching rustygate

dialoghelper calls rustygate’s API through a rustygate comm in a gateway kernel, without a URL or token. Outside one, it sends HTTP to RUSTYGATE_URL. jupyasyncclient.http owns the transport and JSON request mechanics; dialoghelper supplies its gateway configuration and sends the same method, route, query parameters and body over either transport.

browser runs JavaScript in each browser showing this dialog. It opens a browser comm, and Solveit runs the code in every connected browser as the body of an async function. That function receives done, which answers the call, and rid, the call’s id. Code that answers later from an event handler can instead pass rid on and call pushData(rid, {result}), as the solveit-chrome extension does.

The first browser to answer supplies the result. A JavaScript error raises RuntimeError, and no answer within timeout seconds raises TimeoutError. With wait=False, browser returns at once. The code never appears in a cell’s output, so reloading a page doesn’t run it again.

realpath() returns the gateway’s on-disk root. realpath('') returns the current notebook’s folder. Other relative paths use that folder, regardless of the kernel’s cwd. A leading slash uses the gateway root. Targets need not exist. .. can move up within the root, and a path that resolves outside it raises ValueError. realpath makes no gateway call and doesn’t need awaiting, so a $ reference can use it.

These helpers resolve names against dh_settings['path'], the kernel’s notebook, which follows renames. An unbound kernel can resolve root-qualified paths but has no notebook-relative base. list_dialogs() lists the current notebook’s folder by default and keeps the existing notebook-extension and folder-suffix conventions.

data_root

def data_root():

The gateway root recorded at startup, or derived from the current notebook’s folder

The reading and editing tools use Rustygate’s messages API. Rustygate resolves dialog paths, selects messages, converts between message and notebook formats, and applies changes to the current notebook state.

Text edits read content before sending a replacement. Writes do not check whether that content changed meanwhile; the last write to a field wins. Solveit updates its view from the gateway’s broadcasts.

The kernel’s bootstrap records the gateway root in dh_settings['root']. data_root returns it for helpers that use local filesystem paths.

add_msgs

async def add_msgs(
    msgs:list[dict], # Message dictionaries with content and the same per-message options as add_msg
    msgid:str=None, # Message to place the batch beside; defaults to the calling cell in its own dialog
    position:str='after', # 'after' or 'before' msgid, or the dialog's 'start' or 'end'
    dname:str='', # Dialog to add to; defaults to current dialog
)->list[str]:

Add messages in their input order with one request, returning their ids

Without msgid, add_msg places the new message after the calling cell: the cell whose code is running, or the prompt whose tool call is running. position='before' places it before that cell instead. Successive calls therefore come out in reverse order. Use add_msgs to add a list of message dictionaries in input order with one request; each dictionary takes content and the same per-message options as add_msg. When there’s no calling cell, or the message goes to another dialog, it goes at the end, or at the start for position='before'. position='start' and position='end' put it at the dialog’s start or end, whatever the calling cell. The id of the prompt a model is answering is the sid attribute of its <prompt> tag.

Dlg conveniences

These functions manage dialogs and their kernels through rustygate. create_or_run_dialog gets or starts the kernel bound to a dialog, creating the dialog if it’s missing. A new dialog starts with its folder’s TEMPLATE.ipynb cells and settings. When the templates set no mode, it takes the current dialog’s mode. restart_dialog keeps the kernel’s id, and rm_dialog stops the kernel before deleting the file.

Frontmatter and import

Frontmatter is a fenced YAML mapping in physical message zero, whose type must be raw or note (not a prompt). Templates keep placeholder values under formdata. update_frontmatter preserves any text after the closing fence. Invalid or non-mapping headers are ordinary messages; malformed fenced YAML raises an API error.

import_dlg copies a template without running code, filling placeholders, refreshing the dialog or changing browser selection. It assigns fresh IDs, preserves metadata, attachments and prompt replies, and clears ordinary code outputs and execution counts. The selected physical frontmatter merges into the destination with source values winning; nested null deletes a key, maps merge, and arrays and scalars replace. Any nonempty frontmatter body becomes an ordinary note at the import position. A destination frontmatter header stays at message zero even when importing at the start.

Selection and copying happen in one gateway request. The default imports every unskipped message. An ids list imports that exact selection, including skipped messages, in source order; ids=[] imports nothing. Other find_msgs filters select the source messages in Rustygate. Frontmatter merges only when physical message zero is selected. Omitted placement follows the calling cell in the current dialog and appends to an explicitly named destination. position='before' without msgid retains the calling-cell/start convenience.

run_cells runs code cells in a dialog’s kernel through rustygate’s run route: the current dialog’s kernel, unless you pass another dialog’s kernel id. Rustygate saves each cell’s outputs in the cell and sends them to every connected client, as for a run started in Solveit, and run_cells returns them. aidialog’s Message.execute and Dialog.execute differ: they run messages in a temporary in-process shell.

A tool can call run_cells while its own message is still running. Rustygate runs the requested cells in a subshell, so they don’t wait behind the calling message in the main shell’s queue.

When py runs with safepyrun’s audit checks, the nested execution remains inside that audit window. run_cells does not add a separate sandbox.

Prompts

run_prompt asks rustygate to run a prompt. With a prompt message’s msgid, rustygate answers that prompt with the cells above it as context and saves the reply in the message, as when a user runs it in Solveit. With text, rustygate answers a prompt that isn’t in the dialog, using the cells up to msgid as context, and saves nothing. Without msgid, that context ends at the calling cell.

The reply streams back over the comm, and run_prompt prints it as it arrives unless show=False. It returns the reply in the format Solveit stores, with each tool call as a fenced block. Interrupting the cell closes the comm, which cancels the turn, and a prompt message keeps its partial reply. A prompt run from code doesn’t wait in the kernel’s queue. tools names the tools the model may call: functions in the kernel’s namespace, or rustygate’s own exec and spawn_agent.
